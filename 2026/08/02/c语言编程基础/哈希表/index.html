哈希表

哈希表（Hash Table），又称散列表，是根据键（Key）直接访问值（Value）的一种数据结构。它通过哈希函数将键映射到表中的一个位置（桶或槽位），从而实现近乎 O(1) 的查找、插入和删除速度。

我们需要为ht_item定义初始化函数。这个函数会分配一块大小为ht_item结构体的内存，并在新分配的内存中保存字符串k和v的副本。该函数被标记为 static，因为它只会在哈希表内部被调用。

该函数的作用是创建一个新的哈希表条目，并返回指向它的指针。

  • malloc(sizeof(ht_item))：在堆上分配一块内存，大小刚好能放下一个 ht_item 结构体。
  • strdup(k)：复制一份键字符串，并让 i->key 指向这个副本。这样做是因为外部传入的k可能是临时字符串，拷贝一份能保证哈希表内部的数据独立、不受外部影响。strdup(v)同理。
  • 最后return i返回这个新创建的ht_item的指针。

哈希函数与冲突处理

哈希函数是一种将任意长度输入映射为固定长度输出（哈希值）的算法。在我们的哈希表中，哈希函数负责将字符串键转换为一个数组索引，决定键值对应该存放在哪个槽位

  • 每一步都进行 % m，避免溢出。

双重哈希与冲突处理

当两个不同的键计算出相同的索引时，就发生了冲突。开放寻址法需要为冲突的键寻找下一个空位，这一系列索引称为探测序列。我们采用双重哈希生成探测序列，它使用第二个哈希函数来决定步长，能有效避免“聚集”现象，让键的分布更均匀。

  • hash_a：起始位置，由 HT_PRIME_1 算出。
  • hash_b：决定步长，加 1 确保步长至少为 1，避免hash_b = 0导致原地踏步，无法探测下一个位置。
  • attempt：探测次数,每一次冲突，attempt++，算出全新下标

其中HT_PRIME_1，HT_PRIME_2为质数乘数即a，需要提前定义

小结

ht_hash 将任意字符串映射为一个整数，ht_get_hash 利用双重哈希将该整数转化为一个探测序列。两个函数配合，构成了开放寻址哈希表的核心机制——将键均匀地分布到槽位数组中，并在冲突发生时提供高效的替代位置。

后续的插入、查找、删除操作都将围绕 ht_get_hash 生成的探测序列展开。

插入

要插入新的键值对时，我们沿着探测序列遍历槽位，直到找到一个空桶或墓碑标记的位置。
如果发现键已存在，则更新其值；否则在找到的空位放入新条目，并将哈希表的 count 加 1。

几点说明：

  • 负载因子 load = count * 100 / size，一旦超过 70% 就调用 ht_resize_up 进行扩容，以维持较好的性能。负载因子和扩容机制的详细实现将在后文展开。
  • 循环条件cur_item != NULL && cur_item != &HT_DELETED_ITEM确保我们跳过了空桶，也跳过了墓碑，这样能正确找到所有可用的空位。
  • 如果探测过程中发现相同键，直接原地更新值，不会产生重复条目。
  • 只有在确认键不存在时，才调用 ht_new_item 分配新内存,而非提前分配，避免了提前分配带来的潜在泄漏。

查找

查找与插入的流程类似。我们沿着相同的探测序列遍历槽位，在每次迭代中检查当前条目的键是否与目标键匹配。如果匹配，则返回对应的值；如果遇到空桶（NULL），说明目标键不存在，返回 NULL。

几点说明：

  • 查找使用与插入完全相同的探测序列（由 ht_get_hash 生成），保证了能正确定位到键所在的位置。
  • 循环中遇到墓碑标记 HT_DELETED_ITEM 时不能停止，必须跳过继续向后探测，因为目标键可能被冲突推到了墓碑之后。因此必须先判断 item != &HT_DELETED_ITEM 再比较键。

删除

在开放寻址哈希表中，删除操作比插入和查找更复杂。待删除的条目可能处于一条冲突链的中间，如果直接将其移除（置为 NULL），就会切断冲突链，导致链尾部的元素在后续查找时无法被找到。

为了解决这个问题，我们采用惰性删除策略：不真正删除条目，而是将其标记为“已删除”。
具体做法是，将一个全局静态哨兵 HT_DELETED_ITEM 的指针填入槽位，表示该桶曾经有数据但已被删除。

几点说明：

  • 通过将槽位设为 &HT_DELETED_ITEM，查找操作在遇到墓碑时会继续向后探测，不会误判键不存在。这正是前面查找部分跳过 HT_DELETED_ITEM 的原因。
  • 当负载因子低于 10% 时，调用 ht_resize_down 缩小哈希表，节省内存。
  • 只有确实找到并删除了条目，才执行 ht->count--。如果键不存在，保持不变。

随着越来越多的键值对被插入，哈希表会逐渐变满，发生冲突的概率随之上升，导致插入和查找的性能退化。为了维持 O(1) 的平均操作效率，我们需要在表太满时将其扩容，在表太空时将其缩容。

哈希表的扩容与缩容的实现

扩容和缩容的核心操作都是创建一个新表、重新插入所有旧条目，最后交换内部数据并释放旧表。

其过程为：

  • 新建一个大小为 base_size的哈希表。
  • 遍历旧表所有槽位，跳过空槽和墓碑，将有效条目重新插入新表。
  • 通过交换 size 和 items 指针，让原表句柄 ht 指向新数据，而 new_ht 指向旧数据,最后调用 ht_del_hash_table(new_ht) 安全释放旧表。
